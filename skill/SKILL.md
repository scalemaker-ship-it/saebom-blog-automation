# 새봄 블로그 자동화

결과물은 파일이 아니라 **saebom_clinic 블로그 임시저장 목록에 들어간 글**이다. 발행 버튼은 누르지 않는다.

브라우저 = **posendy 크롬 포트 12330** (`chrome_use_browser 12330`, 새봄 네이버 로그인). 로그인 화면이 뜨면 사람에게 넘긴다.

## 1. 순서

1. **키워드 확인**: 노션 표에서 이번 글 행(키워드, 롱테일, 제목)을 읽는다. 진료과로 원장을 정한다: 피부 = 오명훈(응급의학과 전문의), 산부인과 = 김샛별 대표원장(산부인과 전문의).
2. **겹치는 글 확인**: `PostTitleListAsync` 로 최근 글 제목을 보고 같은 주제가 있으면 각도를 다르게 잡고 그 글을 같이 읽기 링크로 건다 (예: 11/9 질건조증 원인편 → 11월 3번은 치료편).
3. **사실 수집**: 병원이 실제로 하는 것만 쓴다. 출처는 새봄 기존 글(`analysis/parsed.json`, `PostView`), 유튜브 대본(`bom/youtube/*/transcript.txt`). 확인 안 된 수치, 기간, 마취 방법 등은 쓰지 않는다.
4. **원고**: `content.py` 를 기준 원고 형식으로 쓴다 (§3 말투).
5. **사진**: §4. 1:1 1080, 눈 감은 사진 제외. 남자 원장 글은 GIF 2개.
6. **문서 생성**: `python3 ~/Desktop/kim/bom/blog/tools/sbblog.py <글폴더>` → doc.json + 자동 검사(글자수, 키워드 횟수, 금지 문자/표현) 출력.
7. **에디터 조립**: §5.
8. **임시저장 + 검수**: §6. 90% 미만이면 고쳐서 다시 저장.

## 2. 글 구조 (최근 글 고정 순서, sbblog.py 가 만든다)

제목(노션 그대로) → 본문 제목 블록(28 볼드 2줄 + 초록 19 한 줄) → 대표사진 01 → 인사와 원장 소개 → 진료실에서 듣는 질문 인용 → 분홍 19 키워드 질문 「광주 ○○, ~..?」 → 답 2~3문장 → 목차 표 → 소제목 인용구 3개(아래 줄에 키워드) → 각 섹션 사진, 본문, 표 → 「오늘 이야기를 정리하면」 → 사진 → 진료 시간 안내 문장 → 「자주 묻는 질문」 Q/A 3개 → 「같이 읽기 좋은 글」(가운데) + 링크카드 2개(가운데, large_image) → 유튜브(있으면) → 구분선 → 네이버 예약 카드 → 전화 표 → 카카오톡 카드 → 진료시간 표(제목 「광주 ○○ 진료 안내」, 피부 = 수요일 16시 피부과 / 산부인과 = 월화수 19시) → 지도 → 의료광고 고지 이미지 2장(템플릿 src 재사용).

서식: 나눔마루부리 fs16, 양쪽 정렬 줄간격 2.1, 강조 = 볼드 / 노랑 형광 #fff8b2 / 밑줄(독자 질문 인용) / 초록 #007433(원장명, Q) / 분홍 #f94996 fs19(키워드 질문). 카테고리 번호: 피부 23, 산부인과 13 (`postwrite?categoryNo=`).

## 3. 말투 (2026-11-17 사용자 지시: AI 티 금지, 실제 원장이 쓴 것처럼)

- 첫 줄에 원장 이름으로 인사: 「안녕하세요. 광주 새봄의원에서 피부 진료를 보고 있는 응급의학과 전문의 오명훈입니다.」
- 진료실에서 실제로 듣는 말을 큰따옴표로 인용하고 이어서 설명: 「"보습제도 써 봤는데 그때뿐이에요." 이런 말씀을 많이 하세요.」
- 한 문장 한 문단, 문단 사이 빈 줄. 문장을 억지로 16자에서 끊지 않는다.
- 「~인데요」, 「~하곤 합니다」, 「~거든요」, 「~말씀드려요」 같은 말하는 어미. 해요체 위주, 사실 안내는 합니다체.
- 금지: 「~것, ~입니다」 식 슬로건 문장 나열, 「첫째/둘째」 볼드 기둥을 줄줄이 세우기, 「진심 어린」, 「함께하겠습니다」, 「세 마리 토끼」, 감성 마무리, 엠대시(—), 가운뎃점(·), 최고/유일/완치/보장.
- 효과는 단정하지 않는다: 「연구가 많지 않아 단정하기 어렵습니다」, 「사람마다 달라요」. 바로 진료가 필요한 증상은 분명히 쓴다.
- 지역 키워드(「광주 ○○」)는 본문 4~6회, 첫 인사 근처와 정리, FAQ 첫 질문(붙여쓰기)에 넣는다.
- 사용자가 준 말투 예시: 송도 휴먼피부과 신요섭 원장 「힐로웨이브 주기/유지기간/부작용 총정리」 (진료실 질문 인용 → 공감 → 원리 → 데이터 → 부작용 → 디자인 → 댓글 안내 흐름). 그 글의 감성 마무리 문장은 따라 하지 않는다.

## 4. 사진

- 원본: 네이버 마이박스 공유 폴더 (이레필름, 2026-10-15 촬영) (공유 링크는 로컬 스킬 파일에만 보관) → 사진/1번캠, 2번캠 JPG 649장. 원장별 번호(목록 순번): 오명훈 단독 79~88, 127~143, 465~570 / 김샛별 48~78, 144~157, 372~464 / 두 원장 89~126, 571~609 / 진료실, 시술실, 장비 158~290 / 대기실, 인증패 291~370, 610~648.
- 받는 법: 마이박스 탭에서 `api.mybox.naver.com/service/link/folder/list?shareKey=..&resourceKey=..&startNum=&pagingRow=` 로 목록(resourceNo 는 정규식으로 문자열 추출, JS 숫자 정밀도 깨짐), `thumb2.photo.mybox.naver.com/<resourceNo>?type=m1280_1280_2&shared_url=<authToken>` 을 fetch → blob 다운로드(~/Downloads). 최대 1280px. 번호 붙은 접촉 시트를 만들어 고른다. 목록 JSON 에는 토큰이 있으니 레포에 올리지 않는다.
- https 페이지에서 127.0.0.1 로 fetch/POST 는 막힌다 (Local Network Access). 파일은 다운로드나 `<input type=file>` + `chrome_upload_file` 로 옮긴다.
- **눈 감은 사진 제외 (2026-11-17 지시)**: `tools/eyes <파일들>` (macOS Vision) → L, R 중 작은 값 < 0.22 이면 제외. 0.22~0.25 는 확대해서 눈으로 확인. 아래를 보는 사진(차트 보는 컷)이 자주 걸린다.
- 1:1 크롭: `python3 tools/crop_square.py <img폴더> <접두어> 01=<원본> 02=<원본>@0.5 ...` (얼굴 가운데 기준, @비율로 직접 지정). 파일명 `<키워드붙여쓰기>_NN.jpg`, 01 = 대표(원장 얼굴).
- 글당 8~9장, 한 글 안에서 같은 사진 중복 금지, 3편을 같이 만들면 서로 다른 컷.
- **남자 원장 글 = 유튜브 GIF 2개 (2026-11-17 지시)**: 내용과 맞는 구간에서 원장이 화면에 나오는(컷어웨이 없는) 8초. 원본 = `bom/youtube/ep01_소개/소개.mp4` 등 편집본(자막 포함). 1초 간격 시트로 구간 찾기 → 자막 박스 폭 측정 → 1:1 크롭이 자막을 자르면 1170x1080 크롭 + 블러 배경으로 정사각. 480px, 10fps, 128색, 7MB 이하. 맞는 구간이 없으면 인사 장면(「안녕하세요 새봄의원 응급의학과 전문의 오명훈입니다」, ep01 0:10) GIF.
  ```
  ffmpeg -ss <초> -t 8 -i 소개.mp4 -vf "crop=1080:1080:<x>:0,fps=10,scale=480:480:flags=lanczos,split[a][b];[a]palettegen=max_colors=128:stats_mode=diff[p];[b][p]paletteuse=dither=bayer:bayer_scale=4:diff_mode=rectangle" -loop 0 <접두어>_gif1.gif
  ```
  content.py 에서 `("img", "gif1")` 로 넣는다.

## 5. 에디터 조립 (postwrite)

1. `chrome_navigate https://blog.naver.com/saebom_clinic/postwrite?categoryNo=<23|13>` (newTab, 글마다 lane 다르게). 「작성 중인 글이 있습니다」 팝업이면 **취소**.
2. JS: `HTMLInputElement.prototype.click` 을 file 타입만 삼키게 패치, 숨은 input `#__docfile`, `#__u1..#__u12` 생성.
3. `chrome_upload_file` 로 사진, GIF 를 `#__u1..` 에 하나씩, doc.json 을 `#__docfile` 에.
4. JS: `.se-image-toolbar-button` 클릭 → `#hidden-file` 에 DataTransfer 로 전부 넣고 change → 「사진 첨부 방식」 창에서 `label.se-image-type-label` 「개별사진」 클릭 → image 컴포넌트 path 가 다 찰 때까지 대기.
5. 마지막 빈 문단을 **실제 클릭**(chrome_click_element 좌표)한 뒤, JS 로 SE 입력 iframe(`document.activeElement.contentDocument`)에 URL `ClipboardEvent('paste')` → 같이 읽기 2개, 유튜브 순서로 붙인다 (각 6.5초 대기). oglinkSign 이 붙은 링크카드/oembed 가 생긴다. 링크카드는 직접 JSON 으로 만들 수 없다(서명).
6. `tools/assemble.js` 내용을 chrome_javascript 로 실행 → 자리표시자 치환(이미지 fileName, 링크카드 순서, 유튜브), 링크카드 `align:center, layout:large_image`, 01 만 `represent:true` → `setDocumentData`.
7. `button.save_btn__FuUyN` 클릭 → 「임시저장이 완료되었습니다.」 확인. 끝나면 `delete HTMLInputElement.prototype.click`.

함정
- 임시저장 목록의 삭제 버튼은 **네이티브 confirm** 을 띄워 그 탭의 모든 MCP 호출이 멈춘다. 지울 땐 사람에게 맡기거나 미리 알린다.
- MCP 는 오래 안 쓴 탭을 정리한다(탭 id 가 사라짐). 탭이 없으면 새로 연다.
- chrome_javascript 는 60초 제한. 업로드 대기, 붙여넣기는 나눠서 부른다.
